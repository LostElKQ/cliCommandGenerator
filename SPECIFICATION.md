# Техническое задание: Интерактивный генератор CLI-команд (CLI Command Generator SPA)

Настоящее техническое задание описывает требования к архитектуре, структуре данных, валидации, интерфейсу и развертыванию статического одностраничного веб-приложения (SPA), предназначенного для декларативного конструирования, интерактивной валидации и разбора консольных команд (например, Docker, Git, FFmpeg, OpenSSL, Tar, Rsync).

---

## 1. Цели и назначение системы

* **Устранение синтаксических ошибок:** Предоставление разработчикам и DevOps-инженерам визуального UI-конструктора сложных флагов и параметров.
* **Обучающий контекст (In-place Documentation):** Детальное синхронное аннотирование каждого отдельного аргумента и флага в генерируемой строке.
* **Полная автономность (Client-Only / Local-First):** Отсутствие серверного бэкенда. Приложение должно собираться в статическую директорию (`dist`/`build`) и публиковаться на **GitHub Pages** с поддержкой клиентской маршрутизации.
* **Воспроизводимость и шаринг:** Кодирование полного состояния сформированной команды в URL без обращения к внешним хранилищам или базам данных.

---

## 2. Архитектурный стек и ограничения

* **Фреймворк:** SvelteKit (режим SPA через `@sveltejs/adapter-static` с `fallback: '404.html'`).
* **Типизация и схемы данных:** TypeScript, **Zod** (для строгой валидации UI-полей и парсинга URL-параметров).
* **Стилизация и компоненты:** Tailwind CSS, Lucide Icons (или Tabler Icons).
* **Управление состоянием и URL:** Svelte Stores, `lz-string` (сжатие состояния в URL-хеш или query string).
* **Развертывание:** GitHub Actions пайплайн (Node.js 20+, pnpm/npm, автоматический деплой через официальный экшен `actions/deploy-pages`).

---

## 3. Схема данных и декларативная модель команд

Вся функциональность утилит описывается строгой JSON/TS-декларацией, отделенной от логики рендеринга.

### 3.1. Вариант типизации схемы (TypeScript / Zod)

```typescript
export type ArgumentType = 
  | 'boolean'       // Флаг переключатель (например, --rm, -v)
  | 'string'        // Текстовая строка (например, имя контейнера)
  | 'number'        // Числовое значение (порты, лимиты памяти, битрейт)
  | 'select'        // Фиксированный enum (выбор алгоритма, кодека)
  | 'key-value-map' // Набор пар ключ-значение (ENV-переменные: -e KEY=VAL)
  | 'path'          // Локальный путь или том монтирования (-v /host:/container)
  | 'list';         // Повторяемый список аргументов

export interface CommandRule {
  id: string;
  flag: string;                   // Например, "--publish" или "-p"
  shortFlag?: string;             // Например, "-p"
  type: ArgumentType;
  label: string;
  description: string;
  defaultValue?: unknown;
  placeholder?: string;
  options?: Array<{ label: string; value: string | number }>; // Для select
  dependsOn?: string[];           // ID флагов, без которых данный флаг неактивен
  conflictsWith?: string[];       // ID флагов, взаимоисключающих этот
  validator?: {
    regex?: string;
    min?: number;
    max?: number;
    errorMessage?: string;
  };
}

export interface CommandCategory {
  id: string;
  title: string;
  description?: string;
  rules: CommandRule[];
}

export interface CommandDefinition {
  id: string;
  baseBinary: string;             // Например, "docker", "ffmpeg", "tar"
  subCommand?: string;            // Например, "run", "compose up"
  title: string;
  summary: string;
  categories: CommandCategory[];
}

```

## 4. Функциональные требования

### 4.1. Движок валидации и правил взаимодействия (Rules Engine)

1. **Реактивная фильтрация флагов:**
* Проверка условий `conflictsWith`: если активен аргумент $A$, аргумент $B$ визуально деактивируется (disabled state) с подсказкой о причине блокировки.
* Проверка условий `dependsOn`: если аргумент $B$ требует наличия $A$, контрол $B$ скрыт или заблокирован до включения $A$.


2. **Валидация пользовательского ввода (Inline Validation):**
* Валидация по регулярным выражениям (порты `1..65535`, форматы `IP:Port`, сетевые пути, единицы измерения `1024m`, `2g`).
* Отображение контекстной ошибки под полем ввода без слома генерации всей строки (невалидное поле помечается ошибкой, а в превью подсвечивается предупреждением).



### 4.2. Сборщик и генератор консольной строки (Command Assembler)

* Порядок вывода аргументов:
1. Базовый бинарник (`docker`).
2. Подкоманда (`run`).
3. Булевы флаги без параметров (например, `-d`, `--rm`).
4. Ключевые параметры и флаги с аргументами (`-p 8080:80`, `--name my-app`).
5. Позиционные аргументы (например, имя образа `nginx:alpine`).


* Поддержка переключения стилей синтаксиса:
* Однострочный вид: `docker run -d --name test -p 80:80 nginx:alpine`
* Многострочный вид с экранированием переносов (`\` для Linux/macOS Bash/Zsh и ``` для Windows PowerShell).



### 4.3. Интерактивная подсветка и разбор аргументов (Syntax Explainer)

* Сгенерированная строка в UI должна быть интерактивной: каждый отдельный токен (флаг, аргумент) кликабелен или реагирует на наведение курсора (hover).
* При наведении на токен в командной строке:
* Подсвечивается соответствующий элемент управления в левой панели настроек.
* Всплывает тултип с описанием: назначение флага, значение по умолчанию и ссылка на официальную документацию.



### 4.4. Синхронизация состояния через URL (State Serialization)

* При изменении любого параметра формируется сериализованный сжатый хеш состояния:

$$\text{State} \xrightarrow{\text{JSON.stringify}} \text{String} \xrightarrow{\text{LZString.compressToEncodedURIComponent}} \text{Hash / Query}$$


* При загрузке страницы:
1. Чтение фрагмента URL.
2. Распаковка через `lz-string`.
3. Валидация через Zod-схему для защиты от битых или устаревших структур.
4. Восстановление состояния всех переключателей и инпутов.


* Кнопка **«Share / Copy URL»**: копирование прямой ссылки на текущую сконфигурированную команду.

## 5. Архитектура пользовательского интерфейса (UI/UX)

Интерфейс разделен на три функциональные зоны:

```
+------------------------------------------------------------------------------------+
|  Header: Селектор утилиты (Docker / FFmpeg / Git) | Поиск флагов | Share URL       |
+---------------------------------------------------+--------------------------------+
|  Панель конфигурации (Слева, 60%)                 | Панель результата (Справа, 40%)|
|  - Вкладка/Аккордеон: Сеть и Порты                |                                |
|    [x] Publish Port (-p) [ 8080 ]: [ 80 ]         |  Интерактивная консоль         |
|  - Вкладка/Аккордеон: Ресурсы и Лимиты            |  $ docker run -d \             |
|    [ ] CPU Limit (--cpus) [ 2.0 ]                 |      -p 8080:80 \              |
|  - Вкладка/Аккордеон: Тома и Монтирование         |      --name web nginx          |
|    + Добавить том (-v)                            |                                |
|                                                   |  [Copy] [Toggle Multiline]     |
|                                                   |--------------------------------|
|                                                   |  Explainer Box (Подробности)   |
|                                                   |  -p: Проброс портов хост:конт  |
+---------------------------------------------------+--------------------------------+

```

### Детализация зон интерфейса:

1. **Левая колонка (Конструктор):**
* Поле быстрого поиска и фильтрации флагов (fuzzy search по `flag` и `label`).
* Группировка по категориям (Network, Storage, Security, Performance).
* Визуальная индикация кастомных/измененных значений (badge «изменено»).


2. **Правая колонка (Терминал и Превью):**
* Блок в стиле dark terminal с моноширинным шрифтом (JetBrains Mono / Fira Code).
* Кнопка «Скопировать в буфер» с мгновенной обратной связью (анимация галочки).
* Переключатель оболочки: Bash (`\`) / PowerShell (`` ` ``) / Single line.
* Блок быстрого сброса параметров к дефолтным значениям.

## 6. Нефункциональные требования

* **Zero-Latency UI:** Скорость реакции генератора на ввод текста и клики — строго менее 16 мс (60 FPS без лагов реактивности).
* **Размер бандла:** Общий вес страницы после сжатия (gzip/brotli) — не более 250 КБ.
* **Адаптивность:** Полная поддержка экранов от мобильных смартфонов (вертикальный стек) до широкоформатных мониторов (split-view).
* **Доступность (A11y):** Полная навигация с клавиатуры (Tab, Enter, Space), поддержка ARIA-атрибутов для аккордеонов и переключателей.
* **Поддержка PWA / Offline:** Наличие Service Worker (`@vite-pwa/sveltekit`) для кеширования манифеста и ассетов, обеспечение 100% работоспособности без доступа к сети.
